# tw-taxonomy 專案紀錄——工作日誌、決策紀錄與共通性原則

> 台灣國小學習知識圖譜（以 108 課綱為本）。本文件記錄專案從建立到 v1 完成的完整歷程、關鍵決策與貫穿全程的工作原則，供後續維護、擴充與新成員接手參考。
> 建置期間：2026-07-11 ｜ 最終狀態：v1.0.0 已發布至 GitHub（seyen37 公開＋seyenbot 私有備份）

---

## 一、專案緣起與目標

起點是一份參考專案：教育科技公司 Marble 開源的 [os-taxonomy](https://github.com/withmarbleapp/os-taxonomy)——把多國小學課綱蒸餾成 1,590 個微主題、3,221 條先修關係的 DAG。使用者希望據此建立**台灣本身的版本**。

經分析後確立目標：以十二年國教課綱（108 課綱）國小階段為本，把各領域「學習重點」拆解為細粒度微主題、以先修關係串成有向無環圖（DAG），對應回課綱代碼，供開發者建立個人化 AI 教育工具與兒童學習應用。

## 二、工作日誌（時間軸）

### 前期：分析與定調
- **剖析 os-taxonomy**：clone repo，實測驗證其 DAG 無環（Kahn 拓撲排序 1,590/1,590 通過），釐清四檔資料結構（topics / dependencies / curriculum-standards / clusters）＋Schema＋驗證器＋多層授權（ODbL＋CC BY-SA）。
- **產出分析報告與建置評估**：對照台灣課綱落差（語文完全不可移植、數學高度可移植、社會需在地重建），提出三條路線（翻譯改編／全新重建／混血）。**使用者選定路線 B 全新重建**、全領域、開源＋產品雙軌、本土語文框架級納入。

### 素材蒐集（分批匯入）
- 分四批收齊：**領綱 16 份＋課程手冊 17 份**，涵蓋國小 10 領域（含選修語文）。歸檔到 `sources/`，建收檔清單追蹤，剔除超出國小範圍者（科技、全民國防、第二外國語）。

### Phase 0：骨架
- 建 repo 結構、4 個 JSON Schema、`validate.mjs`（DAG 無環＋階段一致性＋參照完整性＋SHA-256）、README、LICENSE（CC BY 4.0）、PROVENANCE。

### Phase 1：課綱解析
- 開發 PDF 解析器（`scripts/extract/`）：面對四種版面（格線表、三欄說明表、雙欄合併儲存格、多階段並排），最終以「格線表優先＋座標感知備援」雙模式全部收服。
- 產出 **15 科 1,840 條學習重點**（學習內容＋學習表現），跨科抽核逐字比對原 PDF 吻合。

### Phase 2-4：微主題拆解（569 節點）
- **Phase 2 數學**（試點→全年段）：174 節點。先以數學一年級試點校準粒度，通過後擴到 1-6 年級。
- **Phase 3 國語文＋生活**：129 節點。國語文含台灣特有的注音符號鏈（原專案完全沒有）。
- **Phase 4 其餘領域**：英語 29、自然 52、社會 26、綜合 23、健體 24、藝術 18、選修語文各 3（框架級）。
- **表現碼深化**（v0.5）：為自然、健體、藝術補 76 個「表現導向節點」，把三科學習表現代碼覆蓋從 15-35% 拉到 100%。

### 收尾產出
- **clusters 家長摘要**：103 段（領域×主題群×階段）。
- **視覺化 demo**：`viz/index.html`，D3 力導向＋年段分層＋學科上色＋點節點追先修鏈，資料內嵌。
- **教師使用手冊**：涵蓋教案、課程計畫、遊戲化教學的應用，含 Word/PDF 版。

### 韓國參考優化
- 使用者提供韓國 e학습터 相關資料。分析發現 e학습터 已於 2026-02 停運、其課綱對應內建於平台；真正對口的是京畿道《AI 個人化教育指南》。據此做兩項優化：
  - **優化 1 逐課設計表生成器**（`gen_lesson_plan.py`）：用先修關係自動排出逐課教學序列（含教學法、先備、形成性評量）。
  - **優化 2 分級任務**：為每個微主題加進階／基本／基礎三級任務，**全 569 節點 100% 完成**。

### GitHub 發布與雙帳號備份（v1.0.0）
- **發布整備**：補齊 `CITATION.cff`（CFF 1.2.0，type: dataset，CC BY 4.0）、`CONTRIBUTING.md`（貢獻流程＋驗證即閘門）、`.gitignore`（排除 `sources/` 課綱原始 PDF 約 200MB、`__pycache__`、`*.pdf`），並打包 `tw-taxonomy-v1.0.0.bundle` 作離線備援。

- **私有備份**：`seyenbot/tw-taxonomy`（private）留作備份。**沿用使用者 personal-playbook 既有備份房規**：git 一律主機端跑、備份用 SSH host 別名 `github-backup`（＝seyenbot 專用金鑰，`~/.ssh/config` 早設好）。交付兩支主機端腳本 `setup-backup.cmd`（一次性設好 backup remote）與 `sync.cmd`（日常一鍵 commit＋雙推）。首推 109 物件成功，兩端同步就位。

## 三、決策紀錄（ADR）

以下記錄影響專案走向的關鍵決策、當時的考量與結果。

### ADR-1：全新重建（路線 B），而非翻譯 os-taxonomy
- **決策**：不 fork 翻譯，改以 108 課綱從頭建。
- **理由**：os-taxonomy 的語文（英語 phonics）與社會（英美史觀）內容對台灣完全錯置，翻完仍要大改；全新建可完全貼合課綱、授權自主、可自訂注音與本土語文等台灣特有領域。
- **結果**：授權採 CC BY 4.0（比原專案 ODbL/BY-SA 更利社群採用）；成品在結構上比原專案更完整。

### ADR-2：微主題化，而非照抄課綱條目
- **決策**：把課綱一條（如數學 N-1-1「一百以內的數」）拆成多個可獨立教學驗收的微主題（唱數→點數→基數→…→大小比較共 10 個）。
- **理由**：課綱條目粒度不一，拆成單一可教概念才能做個人化路徑推薦與診斷。
- **結果**：569 微主題，每個自帶 evidence 與 assessmentPrompt。

### ADR-3：學習內容與學習表現分開對應
- **決策**：Schema 用 `contentCodes[]`＋`performanceCodes[]` 兩個陣列，而非 os-taxonomy 的單一 standards[]。
- **理由**：108 課綱的「學習重點」本就是學習內容＋學習表現雙軸，正交關係應如實保留。
- **結果**：兩軸皆近 100% 覆蓋；也讓「表現導向節點」的設計順理成章。

### ADR-4：本土語文採「框架級」納入
- **決策**：原住民族語 16 族、新住民語 7 國不逐族／逐語系拆，每語文只建語系中立的三階段能力進程（各 3 節點）。
- **理由**：逐語系拆會使節點數爆炸且維護困難；框架級已能表達能力進程，深化留 v2。
- **結果**：選修語文 18 節點，誠實標註為框架級。

### ADR-5：主題式領域採整合粒度＋能力主旨重寫
- **決策**：自然、社會、綜合、健體、藝術等主題式領域，一個節點掛數條相近課綱碼；描述不抄 PDF 原文，改以能力向度主旨重寫。
- **理由**：這些領域的課綱條文在 PDF 有嚴重跨欄拼接雜訊（如「察覺科學家們是來自於真實是利用不同的…」），照抄會產生亂碼；主旨重寫更乾淨可讀。
- **結果**：描述家長可讀；但誠實分層標示這些科的粒度較整合。

### ADR-6：借鏡韓國的「診斷—分級—導航」流程，而非內容
- **決策**：韓國指南的價值不在課綱內容（與台灣不同），而在「用課綱結構驅動個人化教學」的流程。據此做逐課設計表生成器與三級分級任務。
- **理由**：我們的先修 DAG 在結構上比韓國更完整（他們的先修只隱含在課次順序），但缺「怎麼用圖帶路」的導航。
- **結果**：補上兩支導航——自動排課＋三級分級，全 569 節點分級任務 100%。

### ADR-7：git 只在主機端跑，sandbox 不動 `.git`
- **決策**：所有 git 操作（init／add／commit／push）一律在使用者 Windows 主機端執行；Cowork sandbox 只負責寫檔與備料，絕不在掛載目錄動 git。
- **理由**：實測 sandbox 對掛載的 `.git/` unlink 權限不完整，`git init` 會截斷 `config`、留下無法刪除的 `config.lock`／`index.lock`，反而害主機端後續 git 全數 exit 128。這與使用者 personal-playbook 2026-05-13 的 sandbox／host git-lock 事故同源。
- **結果**：改「sandbox 備料 → 主機端腳本收尾」模式，94 檔順利發布；`sync.cmd` 內建開頭清 `index.lock` 的保險。

### ADR-8：雙帳號備份採 SSH host 別名，而非 HTTPS dual-push
- **決策**：備份到第二帳號 seyenbot 用 SSH host 別名（`git@github-backup:seyenbot/...`，別名對應 seyenbot 專用金鑰），設為獨立的 `backup` remote；不採「單一 origin 掛兩個推送網址」的 HTTPS dual-push。
- **理由**：HTTPS dual-push 只能帶一組 seyen37 憑證，推 seyenbot 的 private repo 會「Repository not found」（無權限）。SSH 別名讓每個帳號各自用自己的金鑰認證，乾淨且免交互輸密碼。此法直接沿用使用者 personal-playbook 既有慣例（該 repo 本身即如此備份），不另造新輪子。
- **結果**：首推 109 物件成功，seyen37（public）＋seyenbot（private）兩端同步；日後改動雙擊 `sync.cmd` 即一鍵雙推。

## 四、共通性原則（貫穿全程的工作方法）

這些原則不是一開始就寫死的，而是在過程中反覆驗證、確立為房規。

### 原則 1：驗證即閘門，絕不靠肉眼
每個資料產出都必須通過機器驗證才算數。`validate.mjs` 檢查：DAG 無環（Kahn 拓撲排序）、階段一致性（先修階段 ≤ 後續）、參照完整性（每個代碼與邊端點都解析得到）、SHA-256 校驗和、分級任務結構。**驗證器在做事**——它實際抓到過方向寫反的跨領域邊（被階段檢查擋下）與課綱文字截斷。

### 原則 2：以課綱代碼為錨，資料可回溯
每個微主題都掛回課綱的學習內容與學習表現代碼。這讓資料可稽核（能追回課綱出處）、可驗收（覆蓋率可量化）、可信任（不是憑空生成）。這也與國際做法一致（韓國成就標準碼、美國 CCSS）。

### 原則 3：誠實分層，不假裝完整
對品質有落差的部分明白標示：核心科（數/國/英/生/社/綜）內容＋表現近 100%；自然/健體/藝術的表現碼原為整合掛碼（後補到 100%）；選修語文為框架級。寧可標清楚邊界，不誇大覆蓋。

### 原則 4：全形標點鐵則
所有描述性中文欄位（description、assessmentPrompt、分級任務）禁用半形標點，由 build 腳本守門檢查。例外：英語科的英文例句本應用半形，守門對該科放寬。

### 原則 5：試點先行，再規模化
數學先做一年級試點校準粒度，通過才擴全年段；分級任務也先數學一年級試點。避免在錯的粒度上做完 569 個節點才發現要返工。

### 原則 6：工具化與可重生
重複性工作寫成腳本而非手工：解析器、`build.py`（多領域＋autolink＋孤島修補＋環檢查＋迭代式 centrality）、`gen_lesson_plan.py`、`apply_diff_generic.py`。資料改動後所有衍生產物（逐課表、manifest、視覺化）都能一鍵重生。

### 原則 7：QODA 協作——重大決策等 sign-off
非小事決策（路線、範圍、授權、深度）都以「問題→選項→建議→等核准」四步進行，等使用者明確 sign-off 才動手，不假設 OK。全程的路線 B、框架級、雙軌用途等都經此確認。

### 原則 8：中心性標地基，排課有優先序
用 centrality（可達後代數）標出「解鎖最多後續」的地基概念（如一對一點數、唱數）。這些不能趕、不能跳，是排課與補救教學的優先鞏固對象。

### 原則 9：沿用既有房規，不另造新輪子
發布與備份不從零設計，而是先讀使用者 personal-playbook 的既有慣例（主機端 git、SSH 別名雙帳號、null-byte 防護）直接沿用。好處是與使用者其他專案一致、金鑰與 SSH 設定現成可用、踩過的雷（git-lock）不再重踩。原則：接手既有工作環境時，先盤點對方已驗證的做法，優先複用而非發明。

## 八、v1.1 改版：教師工作台（2026-11-05）

### 緣起
v1.0 的資料層完整，但使用端只有一張互動圖與需要 Python 的產生器，老師碰不到專案的核心價值。第五節自評的空白「有更好的地圖，但還沒畫出怎麼用地圖帶路」（診斷—分級—回饋流程）也還沒補上。經 QODA 比較三案（只整理／教師工作台／加學生紀錄後端），使用者選定「教師工作台」，並同意產生器改為 JavaScript 單一實作。

### 做了什麼
- **教師工作台 `app/`**：查詢、學習路徑、診斷補救、教學設計表、知識圖五個分頁；雙擊即可離線使用，手機可用，支援深色模式與列印。
- **核心函式庫 `lib/taxonomy.js`**：查詢、上下游、拓撲排序、教學設計表、診斷演算法，網頁與指令共用。
- **診斷補救演算法**：由目標概念往上游廣度優先檢核；答「會」則其必備先修全部推論為會、不再檢核；答「不會」則展開其先修。結束後「補救起點」＝不會且先修皆會的概念，「補救順序」＝不會的概念做拓撲排序。
- **產生器改寫**：`gen_lesson_plan.py` → `gen-lesson-plan.mjs`。改寫前保存 Python 版 150 種組合（15 領域 × 年級／學習階段／全部）的輸出，JS 版逐字比對 150/150 一致才移除 Python 版。
- **整理**：`lesson-plans/` 由腳本重新產生，移除 4 份新舊並存的過期檔（如「第三」與「第3」）；`docs/` 分為 guides／research／build-log；`scripts/pilot-math/` 更名為 `build-topics/`（內容涵蓋全部領域）；`viz/index.html` 改為轉址。
- **自動化**：GitHub Actions 每次推送跑驗證與測試；`main` 更新時發布到 GitHub Pages。

### ADR-9：共用核心採 UMD 一般 script，而非 ES modules 或建置工具
- **決策**：`lib/taxonomy.js` 用 UMD 寫法，瀏覽器以 `<script>` 載入、Node 以 `require` 載入；網頁不用 React、Vite 等建置工具。
- **理由**：Chrome 禁止 `file://` 載入 ES modules，老師雙擊 `index.html` 會失效；零建置也延續專案「零依賴、主機端可直接改」的風格。
- **結果**：同一份邏輯同時服務網頁與指令，不會出現兩套實作結果不一致的問題。

### ADR-10：衍生產物入庫，並由驗證器把關同步
- **決策**：`app/data.js` 與 `lesson-plans/` 由腳本從 `data/` 產生並提交進 repo；`validate.mjs` 會重新產生並比對，不一致就失敗。
- **理由**：雙擊開啟與 GitHub Pages 都需要現成檔案；但手動維護一定會漂移（v1.0 的視覺化資料內嵌在 HTML，就是不會跟著 `data/` 更新的例子）。
- **結果**：延續原則 1「驗證即閘門」，擴大到衍生產物。

### ADR-11：D3 隨專案附帶，CDN 只當備援
- **決策**：`app/vendor/d3.min.js`（7.8.5，ISC 授權）入庫；知識圖分頁才按需載入，失敗時改用 CDN。
- **理由**：學校網路常受限或不穩，離線也要能用；D3 原本就是依賴，只是改為本地優先。
